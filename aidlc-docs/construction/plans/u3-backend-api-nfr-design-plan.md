NFR要件（`../u3-backend-api/nfr-requirements/`）で方向性はほぼ確定（低コスト最優先・単一リージョン・サーバーレス・PITR・厳密SLAなし）。
本計画では、NFR設計で「実質的な選択が残る」点のみ確認する。回答後に設計パターンと論理コンポーネントを確定する。

## 確定済み（再確認不要）
- スケール: DynamoDB On-Demand / Lambda 従量（プロビジョンド同時実行なし）
- 可用性: 単一リージョン（東京）、マルチAZはマネージド内包、厳密RTO/RPOなし

- 信頼性: 全外部呼び出しにエラーハンドリング、fail-closed、グローバルエラーハンドラ

A) **同期送信**（Lambda内でSESを直接呼ぶ）。送信失敗しても問い合わせ本文はDBに保存済みで管理画面から確認可。最安・シンプル（AI推奨）

B) 非同期送信（SQS + Lambda でリトライ強化）。信頼性は上がるが構成が増える

## Q-D2: 問い合わせフォームの二重送信対策（冪等性）
