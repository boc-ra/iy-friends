## 1. インテント分析サマリ (Intent Analysis)

| 項目 | 内容 |
|---|---|
| **ユーザーリクエスト** | 既存サイト `http://iy-o-endan.com/`（小学生ミニバスケットボールクラブ「IYフレンズ」公式サイト）を、AWS 上で本番品質にリニューアルする |
| **リクエスト種別** | New Project（既存の無料HP作成サービスからの実質的な作り直し／Migration 的側面あり） |
| **スコープ見積り** | System-wide（フロントエンド・バックエンド・インフラ・CMS・認証を含む） |
| **複雑度見積り** | Complex（認証付きCMS、未成年PIIの取り扱い、AWSサーバーレス本番運用） |
| **位置づけ** | 本番運用を見据えた本格的なアプリケーション |

### 現行サイトの分析（参考）
- 運用基盤：無料HP作成サービス（hp-ez.com）上、2008年頃から運用
- 主なセクション：TOP／プロフィール／あゆみ／部費・規約／Fclub規約／お問い合わせ／監督達の声（ブログ）／各コーチから（ブログ）／みんなの広場（掲示板・コメント）／写真ギャラリー／チーム連絡／ルールブック／カレンダー／メンバー募集案内
- 主な利用者：チームメンバー（子供・保護者・OB/OG・コーチ・スタッフ）＋一部の外部（入部検討者など）

## 3. 機能要件 (Functional Requirements)

各要件に一意の ID を付与する（FR-xx）。優先度は MoSCoW（Must / Should / Could）で示す。

### 3.1 公開サイト（一般閲覧・ログイン不要）
| ID | 要件 | 優先度 |
|---|---|---|
| FR-01 | トップページで、チーム紹介・最新のお知らせ・最新ブログ記事を表示する | Must |
| FR-02 | 「プロフィール」「あゆみ（沿革）」などの静的な紹介ページを表示する | Must |
| FR-03 | 「部費・規約」「Fクラブ規約」「ルールブック」等の規約系ページを表示する | Must |
| FR-04 | ブログ（監督達の声／各コーチから）の記事一覧・カテゴリ・アーカイブ・個別記事を閲覧できる | Must |
| FR-05 | お知らせ（チーム連絡）の一覧・個別を閲覧できる | Must |
| FR-06 | カレンダー（活動予定・試合日程等）を閲覧できる | Should |
| FR-07 | メンバー募集案内ページを表示する | Should |
| FR-08 | お問い合わせフォームから問い合わせを送信できる | Must |
| FR-09 | 全ページがスマートフォン／タブレット／PC でレスポンシブに表示される | Must |

### 3.2 管理機能（CMS・要ログイン）
| ID | 要件 | 優先度 |
|---|---|---|
| FR-10 | 管理者・編集者はブラウザ上の管理画面にログインできる | Must |
| FR-11 | ブログ記事の作成・編集・削除・公開/下書き管理ができる（カテゴリ付与含む） | Must |
| FR-12 | お知らせ（チーム連絡）の作成・編集・削除・公開管理ができる | Must |
| FR-13 | お問い合わせの受信一覧を管理画面で確認・管理できる（既読/対応状況など） | Must |
| FR-14 | 管理者はコーチ・スタッフを招待して編集者アカウントを追加できる（〜10名程度） | Must |
| FR-15 | 静的な紹介・規約ページの文言を管理画面から編集できる（または容易に差し替えられる運用） | Should |
| FR-16 | 写真ギャラリー機能の枠は用意するが、初期リリースでは写真掲載は行わない（後日有効化） | Could |

### 3.3 お問い合わせ処理

## 6. セキュリティ要件（拡張：Security Baseline 有効・ブロッキング）

本プロジェクトはセキュリティ拡張を **Full（ブロッキング）** で適用する。各ステージで下記 SECURITY-01〜15 の適合性を検証する。要件レベルで特に重要な項目：

| ID | 本プロジェクトでの適用方針 |
|---|---|
| SECURITY-01 | DynamoDB・S3 等は保存時暗号化、全通信は TLS1.2+ を強制 |
| SECURITY-02 | CloudFront／API Gateway のアクセスログを有効化 |
| SECURITY-03 | Lambda 等に構造化ロギング（相関ID付）。PII・秘密情報はログ出力しない |
| SECURITY-04 | HTML 配信に CSP / HSTS / X-Content-Type-Options / X-Frame-Options / Referrer-Policy を付与 |
| SECURITY-05 | 全 API 入力をスキーマ検証（型・長さ・形式・サニタイズ・インジェクション対策） |
| SECURITY-06 | IAM は最小権限（ワイルドカード禁止、読み書き分離） |
| SECURITY-08 | 管理系エンドポイントはデフォルト拒否＋サーバー側での認可・ロール検証、CORS はオリジン限定 |
| SECURITY-09 | デフォルト認証情報禁止、S3 パブリックアクセスブロック、本番エラーは詳細非表示 |
| SECURITY-10 | 依存はロックファイルで固定＋脆弱性スキャン、`latest` タグ不使用 |
| SECURITY-12 | Cognito による認証。**秘密情報の平文保管禁止（Secrets Manager 利用）**、MFA を管理者に必須、ブルートフォース対策 |
| SECURITY-13 | CDN 経由の外部スクリプトは SRI、重要データ変更は監査可能に |
| SECURITY-14 | 認証失敗・認可違反のアラート、ログ保持90日以上 |
| SECURITY-15 | 全外部呼び出しにエラーハンドリング、fail-closed、汎用エラーメッセージ |

### 残課題（要対応）
| ID | 内容 | 状態 |
|---|---|---|
| SEC-ACT-01 | `Document/AWS.md` の平文パスワード削除 | ✅ 対応済（削除確認済み） |
| SEC-ACT-02 | 当該 AWS アカウントのパスワードのローテーション（変更） | ⏳ 要対応（推奨） |
| SEC-ACT-03 | ルートアカウント常用の停止・IAM ユーザー/ロール＋MFA 運用への移行 | ⏳ 要対応（推奨） |
| SEC-ACT-04 | 以後、認証情報・秘密情報はリポジトリに置かず Secrets Manager 等で管理 | ⏳ 方針として順守 |

## 7. テスト要件（拡張：Property-Based Testing 部分適用）

PBT は **部分適用**（純粋関数・シリアライズの往復のみ）とする。
- 適用対象：ビジネスロジックの純粋関数、データのシリアライズ/デシリアライズ往復（例：API⇔DynamoDB モデル変換、日付・カテゴリ整形など）
- 単純な CRUD・UI 表示のみの箇所には PBT を課さない
- 通常のユニットテスト・結合テストは Construction/Build and Test で別途定義

## 9. 成功基準 (Success Criteria)
- 一般閲覧者がログインなしで、チーム情報・ブログ・お知らせ・カレンダー・お問い合わせを閲覧/利用できる
- 管理者・コーチが管理画面からブログ・お知らせを投稿でき、問い合わせを一覧管理できる
- apple-design 基調のレスポンシブUIで、スマホ閲覧が快適である
- Security Baseline（ブロッキング）を全ステージで満たしている
- 小規模・低コスト（サーバーレス）で本番運用できる

## 10. 主要要件サマリ (Key Requirements Summary)
- **公開サイト**：紹介・規約・ブログ・お知らせ・カレンダー・募集・お問い合わせ（ログイン不要）
- **CMS**：管理者/編集者（Cognito）によるブログ・お知らせ投稿、問い合わせ履歴管理、編集者招待
- **廃止**：掲示板/コメント、会員限定エリア、子供の氏名公開、当面の写真掲載
- **技術**：React(TS) / Python / AWS サーバーレス、低コスト運用
- **デザイン**：apple-design 基調・レスポンシブ
- **品質**：Security Baseline（ブロッキング）＋ PBT 部分適用
