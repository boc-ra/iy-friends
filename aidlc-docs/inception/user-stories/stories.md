# ユーザーストーリー (User Stories) — IYフレンズ公式サイト

**方針**（`story-generation-plan.md` 確定方針に基づく）
- 構成：**機能エピック × ペルソナ**のハイブリッド
- 受け入れ基準：**Given / When / Then**
- 粒度：中（1機能＝1ストーリー程度）／ INVEST 準拠
- 優先度：**MoSCoW**（Must / Should / Could / Won't）
- リリース：**Phase 1＝公開サイト＋問い合わせ送信** / **Phase 2＝管理CMS**
- 出典：要件定義書 `requirements.md`（FR-xx）

**凡例**: `[P1]`=Viewer `[P2]`=Prospect `[P3]`=Admin `[P4]`=Editor ／ `Phase 1/2` ／ MoSCoW

---

# EPIC-1: チーム情報・静的ページの閲覧
> 対応要件: FR-01, FR-02, FR-03

## US-01 トップページで最新情報を確認する `[P1][P2]` `Phase 1` `Must`
**As a** 保護者・閲覧者 **I want** トップページでチーム紹介・最新のお知らせ・最新ブログを一目で見たい **so that** サイトを開いてすぐ必要情報に到達できる。
- **Given** サイトのトップにアクセスした **When** ページを開く **Then** チーム名・紹介、最新お知らせ数件、最新ブログ数件が表示される
- **Given** スマホで閲覧 **When** トップを開く **Then** レスポンシブに最適化され、主要導線（お知らせ/ブログ/募集/問い合わせ）に数タップで到達できる
- **Given** 各最新項目 **When** 見出しをタップ **Then** 該当の詳細/一覧ページへ遷移する

## US-02 チーム紹介・沿革を閲覧する `[P1][P2]` `Phase 1` `Must`
**As a** 閲覧者 **I want** プロフィール・あゆみ（沿革）を読みたい **so that** チームの背景を理解できる。
- **Given** ナビゲーションから「プロフィール/あゆみ」を選ぶ **When** ページを開く **Then** 紹介・沿革テキストが読みやすく表示される
- **Given** 個人が特定される情報 **When** ページを表示 **Then** 子供の氏名は伏せられている（DR-05 / PII最小化）

## US-03 規約・部費情報を閲覧する `[P1][P2]` `Phase 1` `Must`
**As a** 閲覧者 **I want** 部費・規約／Fクラブ規約／ルールブックを確認したい **so that** 必要な取り決めを把握できる。
- **Given** 規約系ページを開く **When** 表示 **Then** 各規約が構造化されて読める
- **Given** スマホ **When** 表示 **Then** 表・箇条書きが崩れず読める

# EPIC-2: ブログ「スタッフの声」
> 対応要件: FR-04, FR-11, DR-01, DR-02 ／ 旧「監督達の声」「各コーチから」を単一ブログに統合

## US-04 ブログ記事一覧・アーカイブを閲覧する `[P1][P2]` `Phase 1` `Must`
**As a** 閲覧者 **I want** ブログ「スタッフの声」の記事一覧・アーカイブを見たい **so that** チームの活動の様子を追える。
- **Given** ブログ一覧を開く **When** 表示 **Then** 記事が新しい順に一覧表示され、月別アーカイブで絞り込める
- **Given** 一覧の記事 **When** タイトルをタップ **Then** 記事詳細へ遷移する

## US-05 ブログ記事詳細を読む `[P1][P2]` `Phase 1` `Must`
**As a** 閲覧者 **I want** 個別のブログ記事を読みたい **so that** 内容を把握できる。
- **Given** 記事詳細を開く **When** 表示 **Then** タイトル・本文・投稿日・著者名が表示される
- **Given** 記事本文 **When** 表示 **Then** 子供の氏名は伏せられている（PII最小化）

## US-06 既存ブログ記事の移行データを閲覧する `[P1]` `Phase 1` `Must`
**As a** 閲覧者 **I want** 旧サイトの過去記事（約339件）を新サイトでも読みたい **so that** 過去の記録が失われない。
- **Given** 既存記事が移行済み **When** ブログ一覧/アーカイブを閲覧 **Then** 過去記事が正しい投稿日で表示される
- **Given** 移行対象は当面テキスト中心（写真は除外, Q14） **When** 記事を表示 **Then** 本文テキストが欠落なく表示される（画像プレースホルダは可）

## US-07 ブログ記事を投稿・編集・公開管理する `[P3][P4]` `Phase 2` `Must`
**As a** 管理者/編集者 **I want** 管理画面からブログ記事を作成・編集・削除し、下書き/公開を管理したい **so that** 活動を手軽に発信できる。
- **Given** ログイン済みの管理者/編集者 **When** 記事を作成し「公開」する **Then** 公開記事が一覧に表示される
- **Given** 「下書き」で保存 **When** 一般閲覧者がサイトを見る **Then** 下書き記事は表示されない
- **Given** 編集者（P4） **When** 他人の記事を編集しようとする **Then** 権限に応じて制御される（自記事編集は可、全体権限は Admin のみ）（SECURITY-08）
- **Given** 投稿操作 **When** 実行 **Then** 誰がいつ変更したかが監査可能に記録される（SECURITY-13/14）
- **Given** スマホの管理画面（P3 はスマホ中心） **When** 記事の作成・編集・公開を行う **Then** PCなしでスマホだけで一連の操作が完結できる（モバイル最適化）

- **Given** スマホの管理画面 **When** お知らせを作成・公開 **Then** スマホだけで操作が完結できる（モバイル最適化）

# EPIC-6: お問い合わせ
> 対応要件: FR-08, FR-17, FR-18, FR-19, DR-04

## US-13 お問い合わせを送信する `[P1][P2]` `Phase 1` `Must`
**As a** 閲覧者/入部検討者 **I want** フォームから問い合わせを送信したい **so that** チームに連絡できる。
- **Given** フォームに必要事項を入力 **When** 送信 **Then** 送信完了が表示され、指定メールアドレスへ通知が届く（FR-17／宛先は後から変更可能）
- **Given** 入力値 **When** 送信 **Then** サーバー側で型・長さ・形式が検証される（SECURITY-05）
- **Given** 連続送信・スパム **When** 検知 **Then** レート制限/CAPTCHA 等で抑制される（FR-19 / SECURITY-11）
- **Given** 送信内容 **When** 処理 **Then** 問い合わせデータが永続化される（DR-04）

## US-14 問い合わせ履歴を管理する `[P3]` `Phase 2` `Must`
**As a** 管理者 **I want** 受信した問い合わせを一覧で確認し対応状況を管理したい **so that** 対応漏れを防げる。
- **Given** ログイン済み管理者 **When** 問い合わせ一覧を開く **Then** 受信日時順に一覧表示され、詳細を確認できる
- **Given** 各問い合わせ **When** 「対応済み/未対応」等を更新 **Then** 状態が保存される
- **Given** 権限 **When** 一般利用者がアクセス **Then** 認可により拒否される（SECURITY-08）
- **Given** スマホの管理画面 **When** 問い合わせ一覧・詳細・状態更新を行う **Then** スマホだけで確認・対応できる（モバイル最適化）

# EPIC-7: 認証・アカウント管理（Cognito）
> 対応要件: FR-10, FR-14, SECURITY-08/12

## US-15 管理画面にログインする `[P3][P4]` `Phase 2` `Must`
**As a** 管理者/編集者 **I want** 安全にログインしたい **so that** 権限のある操作ができる。
- **Given** 有効な資格情報 **When** ログイン **Then** 認証され管理画面に入れる
- **Given** 管理者アカウント **When** ログイン **Then** MFA が要求される（SECURITY-12）
- **Given** 連続失敗 **When** 閾値超過 **Then** ロックアウト/遅延等の保護が働く（SECURITY-12）
- **Given** ログアウト **When** 実行 **Then** セッションが無効化される

## US-16 コーチ・スタッフを招待してアカウントを発行する `[P3]` `Phase 2` `Must`
**As a** 管理者 **I want** コーチ・スタッフ（〜10名）を招待して編集者アカウントを追加したい **so that** 投稿を分担できる。
- **Given** ログイン済み管理者 **When** メールで招待を送る **Then** 招待された人が初回パスワード設定を経てログインできる
- **Given** 発行されたアカウント **When** 利用 **Then** 編集者ロール（最小権限）が付与される（SECURITY-06）
- **Given** 不要になったアカウント **When** 無効化 **Then** ログインできなくなる
- **Given** スマホの管理画面 **When** 招待・アカウント管理を行う **Then** スマホだけで操作が完結できる（モバイル最適化）

# EPIC-8: 横断的品質（非機能）
> 対応要件: FR-09, NFR-UX-01..04, セキュリティ拡張, NFR-COST/PERF

## US-17 どの端末でも快適に閲覧する（レスポンシブ） `[P1][P2]` `Phase 1` `Must`
**As a** スマホ利用者 **I want** すべてのページがスマホ/タブレット/PCで最適表示されてほしい **so that** ストレスなく閲覧できる。
- **Given** 任意の画面幅 **When** ページを表示 **Then** レイアウト崩れや横スクロールが起きない
- **Given** apple-design 基調 **When** 閲覧 **Then** 余白・タイポグラフィ・抑制された動きで一貫した体験になる（NFR-UX-01）
- **Given** `prefers-reduced-motion` 設定 **When** 閲覧 **Then** 動きが抑制される（NFR-UX-04）

## US-18 サイト全体でセキュリティ基準を満たす `[P3]（横断）` `Phase 1&2` `Must`
**As a** 運営（プロダクトオーナー） **I want** サイト全体がセキュリティベースラインを満たしてほしい **so that** 子供の情報や運営を安全に守れる。
- **Given** データストア **When** 構築 **Then** 保存時暗号化・TLS強制（SECURITY-01）
- **Given** HTML配信 **When** レスポンス **Then** CSP/HSTS等のセキュリティヘッダが付与される（SECURITY-04）
- **Given** 管理系エンドポイント **When** アクセス **Then** デフォルト拒否＋サーバー側認可（SECURITY-08）
- **Given** 認証失敗/認可違反 **When** 発生 **Then** ログ・アラートに記録される（SECURITY-14）
- **Given** 秘密情報 **When** 保管 **Then** 平文で保持せず Secrets Manager 等で管理（SECURITY-12）

## US-19 低コストで安定稼働する `[P3]（横断）` `Phase 1&2` `Should`
**As a** 運営 **I want** 小規模・低コストで運用したい **so that** クラブの負担を抑えられる。
- **Given** サーバーレス構成 **When** 通常運用 **Then** 月数百円規模に収まる（NFR-COST-01）
- **Given** 初期公開 **When** ドメイン **Then** CloudFront デフォルトドメイン（0円）で公開でき、後から独自ドメイン追加が可能（NFR-DOM-01/02）

## INVEST 準拠メモ
- **Independent**: エピック単位で独立。共通依存（認証=EPIC-7）は Phase 2 に集約
- **Negotiable / Estimable / Small**: 中粒度（1機能=1ストーリー）で見積り可能
- **Valuable**: 各ストーリーはペルソナの価値に紐づく
- **Testable**: すべて Given/When/Then で受け入れ基準を定義
